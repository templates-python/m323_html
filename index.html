M323 – Interaktive Erklärungen

Standalone-HTML-Animationen zum Modul 323 «Funktional Programmieren». Sie werden im Modulwiki per iframe in die jeweilige Theorieseite eingebettet.

LU01 – Einführung

Trace Table: Zeile für Zeile mitschreiben Die Tabelle füllt sich Durchgang für Durchgang, während der Code danebenläuft – lineare Suche und Collatz-Folge. Zeigt unter anderem, warum die Schleife früher abbricht als gedacht.

LU02 – Grundkonzepte

Pure und unpure Functions Dieselbe Funktion, zweimal mit derselben Eingabe aufgerufen – einmal mit globalem Zustand, einmal ohne. Das Aufruf-Protokoll zeigt den Unterschied. By Value und By Reference Schritt für Schritt: was beim Funktionsaufruf mit int und mit list wirklich im Speicher passiert – und warum nur eines der beiden das Original verändert. Objekte, Dataclasses und Standardwerte Warum auch Dataclasses by reference übergeben werden, was frozen=True daran ändert – und weshalb ein [] als Standardwert zwischen zwei Aufrufen überlebt.

LU03 – Erweiterte Konzepte

Rekursion: Call Stack und Aufrufbaum Wie sich vier Frames von factorial(3) stapeln und wieder abbauen – und warum fibonacci dieselben Teilprobleme mehrfach berechnet.

LU03 – Aufträge nach der 5-Schritte-Methode

Diese drei Animationen führen durch die Schritte 1 bis 4 der Anleitung aus lu03:rekursion2 und zeigen bewusst keine Lösung – Schritt 5 bleibt die Aufgabe der Lernenden.

A01 – Rekursive Suche im Verzeichnisbaum Vom einzelnen Element als Base Case über die Suche von Hand bis zur Regel, die jeden Unterordner als dasselbe, kleinere Problem behandelt. A02 – Zinseszins rekursiv gedacht Warum die Laufzeit 0 der Base Case ist, wieso vier Jahre ein Jahr Zins plus drei Jahre sind – und weshalb eine negative Laufzeit den Base Case verfehlt. A07 – Abschreibung rekursiv gedacht Dieselbe Struktur wie A02, nur mit × 0.9 statt × 1.05 – inklusive der beiden Eingabeprüfungen und dem häufigen Denkfehler, vom Anfangswert abzuschreiben.

LU03 – Musterlösungen mit allen fünf Schritten

Dieselben Aufgaben, aber inklusive Schritt 5: der Code entsteht Zeile für Zeile aus den vorher erarbeiteten Regeln und läuft anschliessend durch. Enthält die Lösung – gehört auf die Lösungsseite, nicht auf die Aufgabenseite.

L01 – Verzeichnisbaum: von der Regel zum Code Jede Zeile von find_file wird auf die Regel zurückgeführt, aus der sie stammt – inklusive der Frage, was ohne das return in der Schleife passieren würde. L02 – Zinseszins: von der Regel zum Code Warum der ValueError ganz nach oben gehört, was den Base Case zum Base Case macht – und weshalb Python am Ende 1215.5062500000001 ausgibt. L07 – Abschreibung: von der Regel zum Code Zwei Wächter, ein Base Case, ein Rekursionsschritt – in dieser Reihenfolge, und warum jede andere Reihenfolge die Funktion kaputt macht.

LU04 – Iterables

Generatoren: wann wird eigentlich gerechnet? Warum count_up_to(3) keine einzige Zeile ausführt, wo yield anhält und was dabei stehen bleibt – und weshalb das zweite sum(gen) stillschweigend 0 ergibt.

LU05 – Funktionale Komponenten

Closures: was die Funktion überlebt Der Rahmen der äusseren Funktion verschwindet vom Stack, die Zelle mit ihrer Variablen bleibt. Zwei Aufrufe ergeben zwei unabhängige Zellen – nachgewiesen über __closure__. Decorators: was das @-Zeichen wirklich tut @logged ist nichts als add = logged(add): der Name wird umgehängt, das Original ist nur noch über die Closure erreichbar.
